VG Select: 3A — Deployment Guide

For the engineer deploying VG Select: 3A (Automated Agentic Architecture) as an internal service. Consumers of the running service should read docs/CONSUMER_GUIDE.md.

1. What you are deploying

A single stateless Python process (FastAPI + Uvicorn) that serves:

PathPurpose
/Web UI: guided three-step flow (start from scenario / scan / description, describe the workload, get the recommendation), tooltips on every field, verdict card, comparison table, latency-versus-fit chart, plan and diagram, next steps, and download buttons for the PDF and the LangGraph skeleton
/api/v1/recommendRank topologies for a workload profile; returns the plan and a Markdown report
/api/v1/scan, /api/v1/scan/uploadScan a repository (server path, git URL, or uploaded zip) and infer the profile, then recommend
/api/v1/recommend/pdf, /api/v1/recommend/skeletonArchitecture document (PDF, needs reportlab) and downloadable LangGraph project skeleton (zip)
/api/v1/describeOptional: infer the profile from prose with Claude (needs Anthropic credentials)
/api/v1/fields, /api/v1/examples, /api/v1/topologies, /api/v1/citationsReference data (profile fields, bundled scenarios, topology catalog, citation keys)
/health, /docs, /redoc, /openapi.jsonHealth, Swagger UI, ReDoc, OpenAPI 3 document

The recommendation engine is deterministic and pure Python; the service adds FastAPI/Pydantic and reportlab (PDF generation, installed by the service extra; /health reports pdf_enabled). There is no database. Nothing is persisted; uploaded archives and git clones are extracted to a temporary directory and deleted after the request.

2. Prerequisites

  • Python 3.11+ (3.12 recommended) or Docker.
  • reportlab (pure Python, installed by the service and pdf extras) for the architecture PDF. Without it the PDF endpoint returns 503 and /health shows pdf_enabled: false; everything else works.
  • git on the host only if you enable git-URL scanning.
  • Outbound network access is not required, except for git cloning (if enabled) and the optional Claude-powered describe endpoint (api.anthropic.com). The UI and API have no external front-end dependencies: diagrams are rendered server-side as SVG.

3. Run locally

git clone <this repository> vgselect && cd vgselect
python -m venv .venv && source .venv/bin/activate
pip install -e '.[service]'
export VGSELECT_SCAN_ROOTS=/path/to/repos      # optional: allow scanning by server path
vgselect-service                               # http://localhost:8080

Equivalent: uvicorn vgselect3a.service.app:app --host 0.0.0.0 --port 8080 --workers 2.

Enable the Claude-powered intake (optional):

pip install -e '.[service,llm]'
export ANTHROPIC_API_KEY=...                   # or an `ant auth login` profile plus VGSELECT_DESCRIBE_ENABLED=1

4. Docker

docker build -t vgselect-3a:0.2.0 .
docker run --rm -p 8080:8080 \
  -v /srv/repos:/scan:ro \
  -e VGSELECT_SCAN_ROOTS=/scan \
  -e VGSELECT_ALLOW_GIT_CLONE=0 \
  vgselect-3a:0.2.0

The image runs as a non-root user, exposes 8080, and has a HEALTHCHECK on /health. Mount repositories read-only under /scan. To add the describe endpoint, uncomment the [service,llm] line in the Dockerfile and pass ANTHROPIC_API_KEY as a secret.

Kubernetes sketch

resources: { requests: { cpu: "250m", memory: "256Mi" }, limits: { cpu: "2", memory: "1Gi" } }
readinessProbe:  { httpGet: { path: /health, port: 8080 } }
livenessProbe:   { httpGet: { path: /health, port: 8080 }, periodSeconds: 30 }

Scans of large repositories are CPU-bound (regex over up to 20,000 files, 1 MB per file). Size the CPU limit accordingly or front the scan endpoints with a queue if you expect monorepos.

5. Configuration (environment variables)

VariableDefaultMeaning
VGSELECT_HOST / VGSELECT_PORT0.0.0.0 / 8080Bind address for vgselect-service.
VGSELECT_SCAN_ROOTSempty (path scanning disabled)Colon-separated directories that POST /api/v1/scan {path} may read. Paths outside these roots return 403.
VGSELECT_ALLOW_GIT_CLONE0Set to 1 to allow POST /api/v1/scan {git_url} (shallow clone into a temp dir, deleted afterwards). Only https://, ssh:// and git@ URLs are accepted.
VGSELECT_MAX_UPLOAD_MB50Maximum zip size for /api/v1/scan/upload.
VGSELECT_CORS_ORIGINSemptyComma-separated origins allowed to call the API from a browser on another host.
ANTHROPIC_API_KEYunsetEnables /api/v1/describe when the llm extra is installed. VGSELECT_DESCRIBE_ENABLED=1 enables it when credentials come from an ant auth login profile instead.

6. Security model

The service ships without authentication. Deploy it behind your API gateway, SSO proxy, or service mesh. Anyone who can reach the port can scan whatever the allow-list permits and, if git cloning is enabled, make the host clone arbitrary repositories.
  • Path scanning is deny-by-default. It only works for directories under VGSELECT_SCAN_ROOTS; the check resolves symlinks and rejects traversal.
  • Uploads are size-limited, extracted with a zip-slip check, and deleted after the request. They are never executed. Treat uploaded code as untrusted data; the scanner only runs regular expressions over it.
  • Git cloning is off by default; when on, it is a shallow clone with a 5-minute timeout. Do not enable it on hosts holding credentials you would not want used for cloning.
  • Data leaving the host: nothing, unless describe is enabled, in which case the prose description (not code) is sent to the Anthropic API.
  • No secrets are logged. Scan evidence contains file paths, line numbers and 160-character snippets from the scanned code; the response is returned to the caller only and not stored. The PDF and skeleton contain only the profile, the recommendation and (when supplied) the scan summary the caller sent back.

7. Operations

  • Stateless: scale horizontally; any replica can serve any request. No sticky sessions.
  • Health: GET /health returns {"status":"ok", ...} plus the effective scan roots and feature flags, which is useful for confirming configuration after deploy.
  • Logging: Uvicorn access logs to stdout. Set --log-level warning in production if the access log is noisy.
  • Latency: /api/v1/recommend is a few milliseconds; the PDF takes ~0.1-0.5 s; the skeleton zip is instant. Scans run 0.1-10 s depending on repository size.
  • Timeouts: set your proxy's upstream timeout to at least 60 s for scan endpoints (5 min if git cloning is enabled).
  • OpenAPI: the live document is at /openapi.json; a checked-in copy is in openapi/vgselect-3a.openapi.json (regenerate with python scripts/export_openapi.py). Publish it to your API catalog.

8. Verify the deployment

curl -s http://localhost:8080/health
curl -s http://localhost:8080/api/v1/recommend \
  -H 'content-type: application/json' \
  -d '{"profile":{"task_complexity":"open_ended","steps_predictable":false,"parallel_subtasks":6,"knowledge_sources":4,"retrieval_depth":"exhaustive","tool_count":5,"tool_calls_per_task":40,"latency_budget_s":600},"include_markdown":false}' \
  | python -c 'import sys,json; d=json.load(sys.stdin); print(d["primary"], d["headline"])'
# expected: orchestrator_workers ...

# deliverables
curl -s http://localhost:8080/api/v1/recommend/pdf -H 'content-type: application/json' \
  -d '{"profile":{"name":"smoke","task_complexity":"moderate","tool_count":3,"tool_calls_per_task":3}}' -o /tmp/smoke.pdf && file /tmp/smoke.pdf
curl -s http://localhost:8080/api/v1/recommend/skeleton -H 'content-type: application/json' \
  -d '{"profile":{"name":"smoke","task_complexity":"moderate","tool_count":3,"tool_calls_per_task":3}}' -o /tmp/smoke.zip && unzip -l /tmp/smoke.zip | tail -3

Run the test suite before promoting a build: pip install -e '.[dev]' && pytest (55 tests: engine, scanner, every endpoint, PDF generation, and syntax checks of the generated skeleton for all ten topologies).

9. Upgrading and tuning

  • Bump version in pyproject.toml and src/vgselect3a/__init__.py; the value is reported by /health and in every recommendation.
  • Latency and cost estimates come from MODEL_TIERS in src/vgselect3a/topologies.py (prices, time-to-first-token, tokens/second) and the constants at the top of src/vgselect3a/estimator.py. Replace them with figures measured in your environment; rerun pytest.
  • Rules live in src/vgselect3a/rules.py; each carries a citation key resolved in docs/industry_guidance.md. Add a rule and its evidence together.
  • Scanner pattern tables are at the top of src/vgselect3a/scanner.py; extend them for in-house frameworks or tool conventions.
  • Skeleton templates live in src/vgselect3a/scaffold/langgraph.py (one function per topology). To adapt them to an in-house framework or house style, edit the templates and run pytest; the suite syntax-checks every generated file. To add another framework, register a generator in src/vgselect3a/scaffold/__init__.py.
  • The PDF layout is in src/vgselect3a/pdf_report.py; the colours and header band are constants at the top of the file.
  • Bump the version in the Dockerfile tag and CHANGELOG.md together with pyproject.toml.

Developer preview

.claude/launch.json starts the service on port 8765 for the Claude Code browser preview with tests/fixtures as the scan root. It expects uvicorn and the service dependencies importable by python3; activate a virtual environment with the service extra first.

Also ship the Claude Code skill in .claude/skills/vg-select-3a/ to engineering teams (copy it to ~/.claude/skills/ or their project's .claude/skills/) and set VGSELECT_URL to your deployment so the skill calls the service.
